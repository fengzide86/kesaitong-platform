# 管理定价只读页面证据（2026-10-06）

## 1. 页面和范围

从卖家后台“确定价格 → 管理定价”进入：

```text
/ECrossAmazon/SellerProductList
```

页面通过加密参数中的 `pagemark=3` 切换到定价上下文。当前只读取首屏、筛选控件、列结构和脚本接口，不勾选商品、不修改库存或价格、不打开保存流程。

## 2. 首屏结构

现场页面显示 3 件商品，筛选项包括：

- 商品状态：所有、在售、不可售；
- 配送类型：所有、亚马逊、卖家；
- 价格高于、价格低于；
- 关键词搜索、分页和每页条数。

定价视图的表头包含：状态、图片、SKU 与状况、商品名称与 ASIN/UPC、销售排名、销售历史记录、创建日期与状况更新日期、可售、费用预览、价格 + 运费模板、操作。当前三行的价格相关单元格展示为 `-`，没有把商品原始值写入资料。

批量操作菜单仍存在“停售商品、出售商品、删除商品和报价”，但本轮没有选择商品或执行操作。

## 3. 只读接口上下文

从 `SellerProductList.js` 静态脚本确认，定价页与普通库存页共用读取接口，但上下文不能合并：

```text
POST ../ECrossAmazon/GetSellerProductList
arrayStr: {
  courseId, shopId,
  opType: 1,
  productStatus,
  shipType,
  showType: 0,
  keyword,
  maxPrice,
  minPrice,
  language
}

POST ../ECrossAmazon/GetProductListRepeat
arrayStr: { courseId, shopId, optype: 2, language }
```

`pagemark=3` 会隐藏库存视图中的部分字段，并显示销售排名、销售历史记录等定价相关列。相同的 `GetSellerProductList` 路径必须保留 `pagemark`/筛选上下文，不能把普通库存响应直接当作定价契约。

## 4. 保存边界（仅登记，不执行）

脚本把页面输入编成 XML 后，统一通过以下端点提交：

```text
POST ../ECrossAmazon/DeleteEditProduct
```

静态脚本可见的字段线索为：

- 父商品：`DS2001`、库存 `DS2045`、价格 `DS2071`；
- 子 SKU：`DS2301`、`DS2302`、价格 `DS2305`、库存 `DS2306`；
- 外层还带 `OPType`、`DS20XmlStr`、`DS23XmlStr`、`DS24XmlStr` 和 `language`。

本轮没有改变这些字段，也没有调用保存端点。字段名是脚本线索，尚未把它们扩展成当前账号可重放的写入契约。

## 5. 费用预览分支的只读结论

现场点击“费用预览”后没有出现可填充的费用弹窗。原因是当前三行商品的价格、费用相关单元格都显示为 `-`，页面没有可用于计算的实时商品价格数据；本轮没有继续触发任何价格或商品操作。

静态脚本 `http://www.bjysoft.cn:8732/Scripts/ECross/amazon/SellerProductList.js` 中的 `ViewChargesDetails(ds2001, ds2302)` 显示，费用预览不是另一个已确认的读取接口，而是使用当前页面已经加载的 `p_DS23JsonData` 在浏览器本地组装费用摘要。脚本中的字段/计算线索为：

- 商品价格：`model.DS2305`；
- 配送：固定为 `$0`；
- 买家支付：商品价格加配送的小计；
- 销售佣金：按商品价格乘以 `1 - 0.85` 的脚本估算值；
- 其他费用、费用折扣：`$0.00`；
- 税费：当前脚本展示 `--`，计算代码被注释；
- 预估净收入：买家支付小计减销售佣金。

因此，费用字段和公式属于静态脚本证据，不能替代当前账号的实时费用值。要获得实时值，前提是该商品行先返回可用的价格/报价字段；本轮不补造数据，也不把未展开的弹窗记成现场值。

## 5.1 现场错误状态

在页面停留和关闭现场窗口时，后台重复请求出现一次可见的 502 错误：

```text
POST ../ECrossAmazon/GetProductListRepeat
参数：{"arrayStr":"[{\"courseId\":\"11902\",\"shopId\":\"7511\",\"optype\":2,\"language\":\"1\"}]"}
```

页面提示为“网络错误，请勿离开，稍后重试！(502)”，并打开 `Error/AjaxError` 错误页。该错误发生在只读加载/重复检查请求上，没有触发价格保存、商品状态修改或下载；它解释了为什么费用/重复检查分支不能被当作稳定的成功响应。

## 6. 证据等级和下一步

- 现场已见：定价路由、3 件商品、定价筛选、列结构、批量操作菜单和空价格展示。
- 静态脚本已见：`pagemark=3`、读取接口、保存端点及父/子商品价格字段候选。
- 尚未确认：真实价格响应字段、费用明细的当前值、价格保存后的回读、价格警告和自动定价分支；`GetProductListRepeat` 还需要在稳定网络下复核成功响应。

后续若继续，应转到按 SKU 的 FBA 货件只读分支，补请求体和错误/权限状态；自动定价、协议定价和价格警告仍按项目排除范围登记，不进入脚本设计。
