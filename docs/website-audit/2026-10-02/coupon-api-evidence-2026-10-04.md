# V2 优惠券现场 API 补证（2026-10-04）

## 结论与范围

本轮在亚马逊仿真会话中，实际走通一条**选品 → 创建 → 列表和详情回读 → 编辑 → 回读 → 取消 → 已取消回读 → 打开再次运行**链路。本轮未来状态测试券可编辑和取消；旧的“正在进行”优惠券仅显示查看，不能把这种状态限制误判为全平台没有编辑/取消功能。

测试券已取消，仍保留在列表；取消后的“再次运行”只打开了预填创建步骤，**没有再次提交，没有创建第二张券**。本轮未找到删除入口，不能把取消写成删除。

创建、编辑的请求与 HTTP 200 已捕获，但导航后响应正文丢失，业务 Code/Msg 未取回。二者的业务完成依据是同一活动的列表/详情回读。取消取得 HTTP 200、Code=0、Msg=`操作成功.` 以及已取消回读。首次超时长提交则取得真实业务失败 Code=1。

只保留字段、类型、动作与脱敏关系；不保存账号、原始商品 ID、SKU、ASIN、活动 ID、完整 `paras` 或认证数据。测试对象别名为 `coupon-test-20261004`，其界面测试标题是 `KST_API_COUPON_20261004`，编辑后为 `KST_API_COUPON_20261004_EDIT`。

**本文件的网络事件序号来自运行时重置后恢复的新 IAB 会话，序号从新段重新开始。不得与同日其他补证文件中的相同序号合并为同一请求。**恢复后先核对列表只有 3 条既有优惠券，并确认此前填写的测试券尚未保存，再创建本对象；没有把未知结果的操作直接重复提交。

### 2.1 时长校验差异

界面说明显示活动可为 1—90 天，但本轮首次 30 小时提交真实返回：

```text
HTTP 200
Code = 1
Msg = 活动时间不能超过24小时！
```

改为未来 6 小时后完成创建。因此目前只能确认**该次请求被后端按 24 小时上限拒绝，而 6 小时样本可创建**。界面说明与实测校验不一致，不能据界面文字编写 90 天有效规则，也不能从一个样本断言所有课程、所有活动的统一上限。

结束时间输入 `18:00:00`，列表回读为 `17:59:59`。这里只记录单次输入与回读差异；未验证其完整规范、跨日边界或时区。

## 3. SaveCouponsInfo 提交协议

所有本轮创建、编辑和取消均使用 `POST /ECrossAmazon/SaveCouponsInfo`，不是分别猜测 Create/Edit/Cancel 路径。

外层 form 字段 `arrayStr` 为字符串，内容是 JSON 单元素数组。首对象字段如下：

| 字段 | 创建 `optype=0` | 编辑 `optype=1` | 取消 `optype=2` |
|---|---|---|---|
| `courseId` | string | string | string |
| `shopId` | string | string | string |
| `ds4801` | string | string | **number** |
| `DS48XmlStr` | string，URI 编码 XML | string，URI 编码 XML | string，空 `ROOT` XML |
| `language` | string | string | string |
| `optype` | number `0` | number `1` | number `2` |

不要把创建/编辑与取消的 `ds4801` 类型强行统一；也不要把小写 `optype` 改为其他接口常见的 `opType`。真实活动标识不保存在本文件。

### 3.1 创建与编辑 XML 字段

`DS48XmlStr` 为 URI 编码 XML，已确认节点层级为 `ROOT/DS48_amz`。

已观察到的字段集合：

```text
DS4814
DS4816
DS4805
DS4806
DS4807
DS4810
DS4812
DS4813
DS4817
DS4824
```

其中标题、日期、折扣、预算、次数限制、受众与 UI 的对应见前表。`DS4810/DS4824` 是选品身份字段，但具体父子身份关系仍待实际值联查，不把它们当作已完成的 SKU/ASIN 映射。

### 3.2 写入结果的证据强度

- 首次失败：请求、HTTP 200、Code=1、业务提示均已捕获；不是前端阻断。
- 创建：请求与 HTTP 200 已捕获，响应正文未取回；列表新券、状态与详情回读确认已创建。
- 编辑：请求与 HTTP 200 已捕获，响应正文未取回；同一券的新标题回读确认已更新。
- 取消：请求、HTTP 200、Code=0、业务提示及已取消状态回读完整。

不能把取消响应的成功码反填到创建/编辑请求；也不能把“未取回响应正文”写成平台没有返回正文。

## 4. 列表与详情读取结构

以下类型是本轮样本的实际形状，不是服务端完整 schema。外层 form 的数字形态字段仍是文本传输；二次 JSON 解析后的字段才使用 number/string 等类型。

### 4.1 GetCouponsList

请求字段：

- `courseId,shopId,status`：form 文本，本次为数字形态。
- `keyword,startDate,endDate`：字符串。

响应中的 `result` 是 JSON 字符串，二次解析后已观察到 `Code:number`、`Msg:null`、`RedirectUrl:null`、`Token:null`。本轮列表读取均为 HTTP 200、Code=0。

`jsonStr` 也是 JSON 字符串，二次解析后为数组；列表项字段：

| 字段 | 类型 |
|---|---|
| `DS4801` | number |
| `DS4805,DS4806,DS4807` | string |
| `DS4808,DS4813,DS4814,DS4816,DS4818,DS4819,DS4820,DS4821` | number |

未独立映射的状态数字和统计字段不按编号猜测含义。列表回读证明本轮测试券先“即将推出”，编辑后标题改变，取消后“已取消”；没有声明全状态枚举已齐全。

### 4.2 GetCouponsDetail

请求 form 字段 `courseId,shopId,ds4801` 均为数字形态文本。详情与再次运行读取均为 HTTP 200、Code=0。

这里只归档字段名和类型，不保存该商品的实际标识、名称、图片地址或 SKU。详情商品字段与提交中的 `DS4810/DS4824` 尚未完成逐值关联。

### 4.3 选品请求

本轮 `POST /ECrossAmazon/GetSellerProductList` 返回 1 个子商品，HTTP 200、Code=0。该次调用的完整请求字段与响应字段未在本文件展开归档；不能直接套用同名接口在库存或秒杀页面的全部参数类型。
