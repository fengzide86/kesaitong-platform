- 旧脚本的“随便填”主要是对象名称、内部备注和部分展示性字段；不能把所有固定值都当成非得分项。

- 当前 V2 主机与旧脚本主机不同：旧脚本不能直接运行作为 V2 验收依据。
- 本页前半部分保留首轮“停在提交前”的静态盘点；后续用户明确授权后的现场写入结果，以 `script-sync-complete-2026-10-03.md`、`live-observations-2026-10-03.md` 和 `network-observations-2026-10-03.md` 为准。
- 任何 `btnSubmit`、`保存`、`确认发货`、`最终确认`、删除规则和国内仓库动作都属于写入或不可逆动作；本页不把旧脚本的点击日志当作业务成功。

## 旧脚本实际执行顺序

### 物流模板

1. 进入 Amazon 卖家后台和配送设置。
2. 创建新模板并输入模板名。
3. 调整国内服务勾选，保留标准配送。
4. 循环删除国际规则，逐组添加国家。
5. 每组填 `pricePerOrder`、`unitPrice=0`、`unitMeasure=2 (Lb)`。
6. 点击保存。

### 广告/促销（旧脚本静态流程）

1. 输入商品编码，进入库存管理并把 `FULFILLMENT=value=2` 作为“亚马逊配送”筛选；这只是读列表过滤，不是把商品转换为 FBA。
2. `广告板块自动化脚本.py` 在筛选后的行读取 SKU、ASIN 和价格；`FBA自动化发货脚本.py` 先从未过滤的普通库存读取父级 SKU，切到 FBA 后主要读取 ASIN/价格，不能把两者写成同一取值顺序。
3. P1：V7.1 扫描广告页全部 `span.asin` 并按 10 个切批；V5.4 使用 `inventory_map` 中的 FBA ASIN 精确点选，不能混称为同一逻辑。
4. P2–P5 轮流对目标商品创建秒杀、优惠券、Prime 折扣和全店促销。
5. 每个分支都有提交/保存按钮；旧脚本没有统一幂等键或提交后完整回读。

### 订单发货

1. 进入订单列表，扫描未发货订单与分页。
2. 读取订单号、产品编号、详情重量和买家国家。
3. 用本地 Excel 运费数据选渠道。
4. 进入国内仓库，按“分拣 → 打包 → 立即发货 → 发货记录”处理。
5. 回到订单确认窗口填配送服务、运单号和物流下拉框，点击最终确认。
6. 成功后刷新列表；无订单时每 120–180 秒轮询，属于持续运行脚本而非一次性验收。

## 当前 V2 可安全复现顺序

只做页面/DOM/XHR 读取，逐页停在提交前：

1. 库存管理：确认 FBA 筛选、SKU/ASIN/价格读取和列表请求。
2. 广告活动：打开类型选择和商品推广创建表单，记录字段与页面请求，不选商品、不填预算、不保存。
3. 秒杀、优惠券、Prime、促销：分别打开创建入口和首屏表单，记录资格提示、字段、日期控件和提交接口，不保存。
4. 配送设置：打开模板列表和新建模板表单，记录服务类型、国家弹窗、价格字段，不创建、不删除。
5. 订单/国内仓库：只读订单行、详情重量、买家国家、库存/发货记录子页，不点分拣、打包、立即发货、确认发货。
6. 登录过期时只刷新当前页；需要重新登录时由用户在可见页面完成，不在脚本或聊天中保存凭据。

## 需要明确对象后才能进入写入验收

每条写入主线至少需要一个明确测试对象、范围和回滚方式：

- 物流模板：新模板名、国家范围、重量、费率、是否允许保留/删除已有规则。
- 广告：单一测试商品、预算上限、日期范围、是否允许真实投放。
- 秒杀/优惠券/Prime/促销：单一商品、折扣、时间、对象数量和撤销方式。
- 发货：单一明确订单、确认物流渠道、是否允许真实发货、异常时停止条件。

在这些信息缺失时，只能继续做页面字段与网络请求采集，不能把“所有行为”解释成无限批量提交。

## ALE-000226 商品源资料缺口与图片核验

本节只说明旧资料中实际保存了什么，不把这些值视为当前 V2 的正确答案或已确认得分规则。本次只读检查了源 JSON、配套复制器文本和本地图片，未运行复制器、未修改商品或提交数据。

### 源 JSON 没有动态变体数据

- 来源文件名以 `0.15kgALE-000226瘦脸仪8$` 开头，内容是 JSON；顶层只有 `simple` 与 `attributes`，分别保存 5 个固定字段和 188 个属性字段。
- 第 3、10 行分别保存 `j-select-proNo: ALE-000226` 和 `external_product_id: ALE-000226`；第 11 行保存 `external_product_id_type: 4`。这些是源商品字段，不构成动态变体行商品编码的填法依据。
- 第 4 行为 `variation_theme: 1`；第 17–18 行的 `color_name`、`color_map` 都是 `12345`。文件没有变体数组、逐变体 SKU、逐变体商品编码、逐变体价格或逐变体图片关联。
- 第 22 行 `standard_price: 5.99` 明确属于售价；第 23 行 `item_sku` 为空。不能把 `5.99` 填作商品编码，也不能从空 SKU 推断当前 V2 自动生成规则。
- 同目录 `商品上架代码（复制＋粘贴）(1)(1).txt` 第 1 行明确注明“V28 简化版（移除变体，只保留基本功能）”。第 116–127 行只定义 `simple`、`attributes` 和五个固定字段；第 149–155 行只枚举基本信息、报价、合规、描述、关键词、更多详情六个 Tab，没有动态变体 Tab。因此它会保存变体主题，但未采集动态变体行，旧 JSON 不能作为完整变体模板使用。

### 图片是七张相同副本与两张损坏文件

- JSON 的 `msterpicpath`、`proNewName` 保存了 10 个旧服务器图片路径/文件名，`proOldName` 的 10 项都是 `图片压缩.png`；这只能证明旧主图列表里有 10 个引用，不能证明有 10 个不同角度，也没有与颜色变体建立关联。
- 本地 `商品图片/瘦脸仪` 目录实际有 9 张 PNG。编号副本 `(2)` 至 `(8)` 共 7 张均为 230,333 字节，SHA256 完全相同：`BE6E87445B730A8B6A371C4A088E1986DFF9FB5C60D899DFE7CA86E0C6E22811`。PNG 分块与解压校验通过，图像为 1000×1000 的同一张绿色双头滚轮产品图，不是不同角度。
- 原文件 `2025_11_19_21_08_37.png` 和无编号的 `2025_11_19_21_08_37 - 副本.png` 虽然大小相同，但哈希不同；PNG 分块分别在文件偏移 16,454 和 32,862 处出现越界长度，图像解码失败。它们应标记为损坏文件，不能据此推断为另外两个角度。
- 当前可用证据只有一种独立产品图内容，对应七份相同有效文件，另有两份损坏文件；没有独立变体图。后续采集应区分“旧资料引用”“本地可用文件”和“当前 V2 页面实际接收/保存结果”。

## FBA 商品推广脚本复核（2026-10-03）

这次对旧版 `广告板块自动化脚本.py` 与 `FBA自动化发货脚本.py` 做了只读复核，重点核对“切换亚马逊配送后是否还要在广告表单额外填写 FBA 字段”：

- 两份脚本都把 `input[name='FULFILLMENT'][value='2']` 作为库存页的“亚马逊配送”筛选；这是只读筛选，不是转换为 FBA。`广告板块自动化脚本.py`（V7.1，第 299–381 行）在筛选后的行读取 SKU、ASIN、价格；`FBA自动化发货脚本.py`（V5.4，第 270–295 行）先读取普通库存父级 SKU，随后切到 FBA（第 297–306 行），再主要读取 FBA 行 ASIN/价格（第 308–347 行），不应写成“两份脚本都从 FBA 行读取三项”。
- 商品推广（P1）进入“广告活动管理 → 创建广告活动 → 继续”后，旧脚本填写活动名称 `DS03S05`、可选广告组名 `DS0307`、日预算 `DS0310`、起止日期 `StartDate/EndDate`。V7.1 扫描页面全部 `span.asin` 后每批最多 10 个；V5.4 使用 `inventory_map` 的 FBA ASIN 精确点选。两者对应 `广告板块自动化脚本.py` 第 386–494 行、`FBA自动化发货脚本.py` 第 364–417 行。
- 两个旧脚本都把同一个 `name` 写入 `DS03S05` 与 `DS0307`；这只能记录“现场标签映射/待抓请求确认”，不能仅凭静态代码断言两个字段的语义。
- P2 秒杀、P3 优惠券使用 ASIN；P4 Prime 使用 SKU（`input.pro_sku`）并填折扣；不能把商品推广的 ASIN 选择和 Prime 的 SKU 字段混用。脚本对应 `广告板块自动化脚本.py` 第 496–635 行。
- ALE-000226 源 JSON 第 23 行 `item_sku` 为空，但第 37–38 行同时保存 `MFN=1`、`AFN=2`，说明旧商品资料支持两种履约标记，不能用空源 SKU 推断当前 V2 的动态 SKU。当前 V2 现场应以“亚马逊库存”页的实际 FBA 行、ASIN 和可选商品状态为准。

因此，若当前“广告活动”商品列表仍为空，优先检查 FBA 筛选是否真正生效、目标商品是否在 FBA 库存行显示、ASIN 是否与广告表单列出的 ASIN 完全匹配，以及页面列表是否已完成异步刷新；不应在广告表单中凭经验增加未出现在旧脚本或页面上的隐藏字段。

## P1–P5 版本差异与结果边界

- V7.1 的 P2/P3/P4/P5 在每个时段通常取 `inventory_map[idx % len]` 的单品轮播；V5.4 的对应任务是遍历 `inventory_map` 全量商品，不能把“每时段一个商品”写成两版共同规则。
- P2 秒杀：按 ASIN 搜索，只有出现“高级编辑/推荐商品”才继续；价格通常取推荐价或当前价减 1（最低值有脚本兜底），日期后点击提交。脚本只根据点击/弹窗日志记成功，没有推荐列表或最终状态回读。
- P3 优惠券：按 ASIN 搜索并走三步表单，旧固定值含折扣金额 `2`、预算展示 `100`、名称与日期；没有稳定清空、重试或提交后列表回读。
- P4 Prime：使用 `input.pro_sku` 和折扣字段 `pro_dis`。V7.1 在验证后检查按钮文案再继续，最低折扣兜底为 `0.01`；V5.4 低于阈值时改为 `1.0`，验证判断更弱，超时可能直接点最后一个提交按钮。
- P5 促销：若存在 `DS1509`，旧脚本选择值 `0`（代码注释称“所有商品分类”，需以页面/请求复核），填写日期、内部描述和跟踪 ID 后保存。该值不能直接当作评分点。
- P1–P5 的“成功”均发生在点击返回 True 或出现弹窗之后；旧脚本没有统一业务 `Code/Msg`、列表状态、详情行、幂等键或撤销回滚。
- 调度也不同：V7.1 目标时段结束小时约为 20、间隔 1；V5.4 目标为次日 09、间隔 4；两者都是单 Driver 顺序执行，不支持真正的并行浏览器任务。
