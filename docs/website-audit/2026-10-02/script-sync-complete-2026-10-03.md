## 2. 旧脚本的共同入口与状态边界

1. Selenium 先打开旧版登录入口，再通过顶部菜单和 iframe 找页面；代码没有独立 REST 客户端，也没有可靠的请求日志、幂等键或统一提交回读。
2. 广告与 FBA 脚本都把 `FULFILLMENT=value=2` 作为“亚马逊配送”筛选，但这不是转换动作。V7.1 广告脚本从筛选行读取 SKU/ASIN/价格；V5.4 先读普通库存父级 SKU，再从 FBA 行读取 ASIN/价格。
3. `广告板块自动化脚本.py` 的 P1 会读取创建广告页全部 `span.asin` 后按每组 10 个分批，存在混入非 FBA 候选的风险；`FBA自动化发货脚本.py` 的 P1 使用 `inventory_map` 中的 FBA ASIN 精确勾选。复现“FBA 商品发广告”时优先采用精确映射版本。
4. 旧代码遇到继续按钮时依赖平台默认的商品推广类型/投放方式，没有单独填写“FBA 广告”字段。当前现场也证明商品推广表单没有额外 FBA 开关。
5. 订单发货脚本是真写入流程，包含持续轮询和最终确认；不能把“旧脚本能点击”当作当前 V2 已可安全执行。

## 4. 当前 V2 的 FBA 广告实测链路

已按用户指定的实际路径完成：

`管理库存 → 选择“转换为‘亚马逊配送’” → 只转换 → 危险品信息（无电池/无危险品） → 保存并继续 → 管理亚马逊库存回读 → 广告活动/广告组回读`

现场回读事实：

- FBA 库存行：SKU `ID-KY21-1APR`、ASIN/UPC `10098F798 / ALE-000226`、FNSKU `9ZSRGSSP4C`、状态“在售”、可售 0、费用预览 `$0.90`、体积 `0.042`。
- 广告组商品行：ASIN `10098F798A`、SKU `ID-KY21-1APR`；它与 FBA 转换后的库存记录一致，但该广告是在 FBA 转换前创建的，因此只能作为映射/回读证据，不能冒充“转换后新建广告”的因果验证。
- Prime：同一 SKU 验证、保存并显示“等待中”。
- 秒杀：仍无推荐；这是活动推荐条件未满足，不是 FBA 转换失败。
- 本轮选择“只转换”，没有点击“转换并发送库存”，因此没有创建 FBA 货件。

## 5. 与当前系统接入的可靠边界

- 旧主机、旧路径、旧选择器、旧课程参数与当前 `bjysoft.cn:8732` 不是同一契约；只能作为步骤和字段线索。
- 进入脚本实现前，必须以当前 FBA 库存行的实际 SKU/ASIN 为主键，再在商品推广页精确选中 ASIN，提交后回读广告组商品明细。
- 页面 HTTP 200 不等于业务成功；必须同时读取业务 `Code/Msg`、页面弹窗、列表状态和详情行。
- 旧资料中的成绩字段、商品模板值、价格、SKU 空值和配送标记都属于历史资料；不得直接当作当前 V2 评分点或动态 SKU。
- 当前商品推广编辑页还暴露竞价策略 `DS0311`、动态/固定竞价 `DS03S12`、默认竞价 `DS03S13`、广告位调整 `DS03S14`–`DS03S21`、否定定向、活动设置 `DS0323`–`DS0326` 等高级字段。旧脚本没有填写这些字段，不能因为页面可见就把它们标为 FBA 必填。
- 当前已确认 FBA 转换后的库存行与商品推广广告组明细可以按同一 SKU/ASIN 回读；但这条广告创建早于本次转换，尚未做“转换后新建一条广告”的因果实验，也尚未证明真实投放效果、秒杀推荐或成绩变化。

## 7. 物流/发货脚本静态风险补充

这部分来自对 `自动化发货主脚本.py`、`创建物流模板脚本.py`、`运费计算器模块.py` 和 `物流比价测试脚本.py` 的逐行只读核对，未运行脚本、未操作页面：

- 旧发货主脚本使用旧主机、旧 iframe/XPath 和单一 Selenium Driver；登录校验失败仍可能继续，分页没有稳定去重，发货记录只按产品号读取且可能读到旧单号。
- 国内仓库的分拣/打包返回 `NOT_FOUND` 或一般 `False` 时，主流程仍可能继续“立即发货”；这不是当前 V2 可安全复用的成功契约。脚本中还有一段在 `return` 之后不可达的重复提交代码。
- 物流代码存在网页值与本地计算器值两套映射；商品重量只取首个数字、没有可靠单位换算；计算器固定 Excel 列和表头，超过 20kg 的 UPS 阶梯没有完整覆盖，体积重/燃油费也不能直接当成实时平台报价。
- 创建物流模板脚本把 `unitMeasure=2` 固定为 Lb，国家选择和规则保存后没有完整列表回读；删除旧规则属于破坏性动作，异常时只打印并继续，没有幂等或回滚。
- 因此当前 V2 只能把“订单行 → 商品重量/国家 → 本地报价候选 → 发货表单 → 业务回读”拆成可验证步骤；不能直接移植旧脚本的无限轮询和最终发货动作。

## 10. 旧脚本静态交叉核对增量（2026-10-03）
