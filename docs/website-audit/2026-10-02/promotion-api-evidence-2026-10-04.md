# V2 购买折扣促销现场 API 补证（2026-10-04）

## 结论与范围

本轮实际走通新测试促销的**创建 → 待生效列表回读 → 编辑详情 → 修改内部描述 → 回读 → 删除 → 删除后回读**。只操作新对象 `KST_API_PROMO_20261004`，编辑后名称为 `KST_API_PROMO_20261004_EDIT`，最终已删除；原有 `KST-PROMO-TEST` 没有被编辑或删除。

创建、编辑的 POST 和 HTTP 200 已捕获，但导航后响应正文未取回，业务 Code/Msg 未知。创建与编辑的实际结果由同一对象的列表和详情回读确认。删除取得 HTTP 200、Code=0、Msg=`操作成功.`，随后**待生效筛选**列表返回空数组，UI 显示 0 个促销、无相关数据；这不是说所有状态下的促销都被清空。

本轮还确认了页面字段与实际 XML 字段并非一一等同：可见的排除商品分类、利益显示文字没有出现在此次提交 XML 中；标准展示文字仍保留旧的“每 8 减 2%”内容，与实际填写的 6/10、12/15 档位不一致。不能只读展示文案判断优惠规则，也不能把未提交的可见字段虚写进请求协议。

下文仅保存测试标签、字段、类型和脱敏关系，不保存账号、活动真实 ID、完整 `paras` 或认证数据。对象别名为 `promotion-test-20261004`。事件序号属于运行时重置后恢复的新 IAB 采集段，与本轮优惠券、Prime 证据沿用同一段；不能与较早会话的同号事件合并或跨段数字排序。

## 4. 读取协议与状态解释

### 4.1 GetPromotionList

本轮使用 `POST /ECrossAmazon/GetPromotionList` 读取待生效列表。既有采集已经确认该接口 form 包括数字形态文本 `courseId,shopId,advertisingType,status`，以及字符串 `keyword,startDate,endDate`。字段类型是 form 文本形态，不要与 `arrayStr` 内部的 JSON number 混为一谈。

本轮三个关键回读均为 HTTP 200、Code=0：创建后 1 条、编辑后同一条新描述、删除后 `jsonStr` 二次解析为 `[]`。从已采集事件 4150 → 4153 归档本次列表项结构（未重新请求平台）：`DS1501, DS1505, DS1506:number`；`DS1535, DS1536, DS1537, DS1538, DS1541, DS1554:string`。不能把该样本结构当作所有活动类型的完整合同。

### 4.2 GetPromotionDetail 与 GetPromotionProductList

编辑页实际先取得商品列表，再取得促销详情，两个请求均为 HTTP 200、Code=0。此前同接口 form 已观察到：

- `GetPromotionDetail`：`courseId,shopId,ds1501,opType` 为数字形态文本。
- `GetPromotionProductList`：`courseId,shopId,ds1501` 为数字形态文本；`keyword,startDate,endDate` 为字符串。

本次商品列表 `jsonStr` 解析为 `[]`，详情可正常读取。这是选择“所有”商品分类时的实际样本；不能仅凭空的关联商品列表否定促销已经保存，也不能凭空补出一个商品关联记录。

从已采集事件 4320 → 4325 补记详情的完整键与本样本类型，不记录原始活动标识和商品内容：

```text
number: DS1501, DS1505, DS1506, DS1507, DS1508, DS1509, DS1510,
        DS1511, DS1514, DS1515, DS1516, DS1517, DS1539, DS1540,
        DS1542, DS1546, DS1549, DS1551
string: DS1513, DS1535, DS1536, DS1537, DS1538, DS1541,
        DS1544, DS1545, DS1547, DS1550, DS1552, DS1553, DS1554

```

三个读取接口外层 `result` 与 `jsonStr` 均为需二次解析的 JSON 字符串；`result` 解析为 `{Code:number, Msg:null, RedirectUrl:null, Token:null}`。列表/详情的 `jsonStr` 为对象数组，本次商品列表为空数组。`null` 只表示此样本没有值，不表示字段类型永远只允许 null。只有已与页面核对的字段才赋予业务含义，其余保留键与类型。
