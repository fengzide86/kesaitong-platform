# 业务动作与操作准备度地图（2026-10-06）

这份地图把商业计划、赛训打法、旧脚本和当前 V2 现场证据接成一条可供后续设计使用的链路。它描述“现在能设计到哪一层”，不是自动化脚本，也不授权创建、修改或提交新的业务对象。

## 1. 准备度定义

| 标记 | 含义 |
| --- | --- |
| R0 | 只有商业资料或静态页面线索，只能作为假设和采集方向 |
| R1 | 现场只读页面/请求已具备，可以设计读取、筛选和状态展示 |
| R2 | 指定测试对象已有受控写入与写后回读，可以设计“动作 + 回读”的流程骨架 |
| G | 需要新的对象、敏感文件或明确人工确认，不能直接进入无人值守流程 |

## 2. 商业链到当前操作单元

| 业务链 | 当前 operation_id | 准备度 | 当前能设计的内容 | 仍需人工确认或新证据 |
| --- | --- | --- | --- | --- |
| 选品/商品资料 | `inventory.list`、商品分类/编辑页静态线索 | R0–R1 | 商品列表、FBA/MFN 筛选、商品编辑页字段分区和前置检查 | 叶子类目动态字段、变体/SKU、校验错误和 `SaveProduct` 写后回读 |
| 配送模板 | `template.lifecycle` | R2（指定样本） | 模板创建/编辑/设默认/恢复/删除的对象状态机、规则读取和回读 | 子 SKU/批量绑定、国家/服务、重量单位、限重、币种、地址规则的逐条持久化 |
| 商品履约 | `fba.convert`、`fba.inventory.list` | R2（指定 SKU） | 卖家配送转 FBA、FBA 库存状态和 FNSKU/体积回读 | 新货件、箱子、标签、承运人、完成和撤销；需要真实测试货件 |
| FBA 货件查询 | `fba.shipment.sku` | R1（当前空结果） | 按 SKU、状态和分页读取货件列表 | 货件对象为空，不能从空数组推导创建或发货协议 |
| 定价 | `inventory.pricing` | R1 | 定价筛选、费用预览入口、502/空值状态和人工复核提示 | 真实报价、保存 Code/Msg、商品列表/详情回读；改价前必须指定商品和回滚值 |
| 商品推广/促销 | `deal.recommendation`、`promotion.prime`、`promotion.discount`、`deal.lifecycle`、`coupon.lifecycle` | R2（指定样本） | ASIN/SKU 前置检查、活动三层 ID、状态回读和取消/删除分支骨架 | 资格、预算、日期、时区、暂停/失败/跨日分支；不能把旧脚本固定值当默认规则 |
| 订单与国内仓库 | `order.seller.list`、`warehouse.order.list`、`shipment.status` | R2（单笔成功样本） | 订单状态 → 仓库分拣/打包/发货 → 卖家确认 → 列表/详情回读 | 缺货、重复提交、物流不可达、超时、跨会话恢复和精确业务 Code/Msg |
| 库存规划 | `inventory.planning` | R1 | 库龄、库存状态筛选、空态和禁用批量动作展示 | 有库存对象后再验证移除订单、匹配最低价和回读 |
| 买家消息 | `buyer.message.list` | R1 | 消息类型筛选、搜索、分页和空态 | 打开正文、发送、回复、附件和权限失败；本阶段不触发 |
| 亚马逊物流设置 | `fba.settings` | R1 | 当前设置状态、分区和选项展示 | 任意设置保存、订阅、承运人或条码偏好变更 |
| 图片上传 | `imaging.upload.page` | R1 | 图片规格、WebUploader 初始化和人工文件预检 | 真实文件上传、失败重试、对象关联和上传后回读 |

这里的 R2 只表示“指定对象的事实已经出现过”，不表示同一操作对所有商品、活动或订单都稳定，也不表示可以批量重放。

## 3. 旧脚本如何映射到新底稿

| 旧资料主线 | 当前对应 | 不能直接复用的部分 |
| --- | --- | --- |
| 创建物流模板脚本 | `template.lifecycle` | `idtrade.cn` 主机、旧选择器、固定服务码和重量单位需要逐项重新确认 |
| 广告板块自动化脚本 P1–P5 | `deal.recommendation`、`promotion.*`、`deal.lifecycle`、`coupon.lifecycle` | P1 的 ASIN 批次与 P4 的 SKU 不能混用；名称、预算、折扣、日期和轮播策略不是平台默认值 |
| FBA 自动化发货脚本 | `fba.convert` + 广告/促销操作 | 文件名不代表真实货件流程；`FULFILLMENT=2` 只是库存筛选，不是 FBA 转换 |
| 自动化发货主脚本 | `order.seller.list` + `warehouse.order.list` + `shipment.status` | 仓库四步与卖家确认必须按同一订单关联，旧脚本没有统一幂等键和完整回读 |
| 物流比价/运费计算器 | 发货前的离线输入预检 | `nan` 国家名、别名重复、体积重和平台显示价格仍需清洗/现场核对，不能直接写入发货表单 |

旧脚本的可取部分是业务顺序和字段来源；不能把旧站点地址、XPath/CSS、固定参数、点击日志或本地计算结果当成当前 V2 协议。

## 4. 后续设计的最小操作契约

每个可进入设计的动作都应先登记以下字段，再决定是否需要浏览器交互或接口观察：

1. `operation_id`：使用上表的业务操作单元，不使用裸 URL 作为唯一标识。
2. `page_context`：页面、宿主、iframe/新标签、`courseId/shopId` 等上下文是否齐全。
3. `object_key`：测试商品、SKU、活动或订单的脱敏短标识；没有对象时只能读列表。
4. `preconditions`：筛选、资格、库存、登录会话和前置状态。
5. `read_request`：method/path、请求触发条件、HTTP 状态和业务 `Code/Msg`。
6. `write_allowed`：默认 `false`；只有明确授权、范围和回滚方式才改为人工确认的单次动作。
7. `readback`：列表、详情或状态计数中必须能看到同一对象的预期变化。
8. `failure_stop`：Code/Msg、重复提交、超时、登录冲突或回读不一致时停止，不猜测重试。
9. `evidence_batch`：记录日期、会话状态、`cursor/truncated/hasMore` 和证据等级。
10. `privacy`：客户信息、订单原文、文件和认证材料不落盘；需要下载时先单独确认范围和清理方式。

## 5. 人工确认闸门

以下动作在没有新的明确对象和回读判据前保持人工确认：

- 创建真实 FBA 货件、箱子、标签、承运人或完成入库；
- 改价、创建或提交新的广告/活动、改变物流模板有效规则；
- 发送/回复买家消息，上传图片或提交商品动态表单；
- 真实订单分拣、打包、立即发货和最终确认发货；
- 下载可能含客户信息的订单报告。

## 6. 与商业计划的关系

商业计划提出的“个人工具箱 → 批量工作台 → 内部运营端”可以先用 R1/R2 操作单元拆出最小可验证流程：先读懂对象和状态，再对一个明确对象做一次动作，最后以回读判断成功。当前证据能支持产品范围、页面分层、字段来源、人工介入点和验证顺序；不能单独证明市场规模、评分提升、收入、无人值守稳定性或平台全部规则。

后续若开始做工具，建议先从 `inventory.list → fba.convert → fba.inventory.list` 或 `order.seller.list → warehouse.order.list → shipment.status` 中选一条已有 R2 的链路，保留人工闸门，再逐步接入异常分支。不要从空的 FBA 货件、定价保存或消息发送开始扩张范围。
