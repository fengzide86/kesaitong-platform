# V2 FBA 转换与危险品现场补证（2026-10-04）

## 结论与证据边界

本轮在同一 Codex 内置浏览器会话中，展开管理库存的父商品变体，从一个仍由卖家配送的**子 SKU**进入转换流程；页面读到 1 个待转换 SKU，完成危险品信息，再提交“保存并继续”。随后库存接口和页面均回读到同一子 SKU 已具备 FBA 标识、FNSKU 和“转换为卖家配送”的反向操作入口，可售数量为 0。

因此，本样本已经实际转换并回读，不能继续归为“转换页 0 SKU、无法提交”。但写入接口 `SaveDeliveryWay` 的 HTTP 200 已捕获，**响应正文因导航后的 `No resource found` 未取回，业务 Code/Msg 尚缺**；不能写成 Code=0，也不能宣称 FBA 字段级完整验收。

样本匿名别名：`fba-child-sample-20261004`。不保存原始 SKU、ASIN、FNSKU、商品/变体 ID、账号、完整 `paras`、Cookie 或 Token。API 路径为本次真实事件，不由旧脚本名称猜测。下文事件序号仅用于本次采集关联，不能跨会话复用。

## 1. 本次实际执行链

```text
管理库存
→ 展开父商品的变体箭头
→ 选择卖家配送的子 SKU 行
→ 转换为亚马逊配送
→ GetProductSkuListByProduct：1 个 SKU
→ 危险品信息页及 iframe
→ 逐项切换 是 / 否 / 不确定
→ 提交 否 / 否；主表显示危险品信息已完成
→ 保存并继续：SaveDeliveryWay
→ 库存重新读取：GetSellerProductList
→ 同一子 SKU 回读 FBA / FNSKU / 转换回卖家配送入口
```

这里至少包含三个不同动作：库存筛选、对子 SKU 执行配送方式转换、后续广告商品选择。**“亚马逊配送”筛选不是转换提交，FBA 转换也不等于广告候选一定可用。**

历史记录中“0 SKU”是当时对象/选择上下文的观测；本轮有明确子 SKU 的成功分支。尚未做严格对照实验，不能据此断言历史空列表唯一原因就是选择父行。

## 3. 请求编码与字段

### 3.1 SKU 读取

外层 form 字段 `arrayStr` 是字符串，解码为单元素 JSON 数组。对象字段为：

| 字段 | 主页面/危险品页 | 危险品 iframe | 说明 |
|---|---|---|---|
| `courseId` | string | string | 课程上下文，不保存值 |
| `shopId` | string | string | 店铺上下文，不保存值 |
| `DS20DS23XmlStr` | string | string | URI 编码 XML，结构见下文 |
| `language` | string | number | 同一接口不同调用方确有类型差异，不能擅自抹平 |

XML 结构（仅占位符，无原始 ID）：

```xml
<R><P><DS2001_t><![CDATA[ID]]></DS2001_t><DS2302_t><![CDATA[ID]]></DS2302_t></P></R>
```

两个 ID 键分别对应哪一层对象，仍需与当前商品/变体读取结构核对。不能只依据编号命名推定含义。返回项的完整 DS 字段类型仍待归档。

### 3.2 配送方式提交

外层 form 字段：`arrayStr`，其内容为 JSON 数组，本次取首个对象：

| 字段 | 解码后的类型 | 本次证据 |
|---|---|---|
| `courseId` | string | 当前课程上下文；不保存值 |
| `shopId` | string | 当前店铺上下文；不保存值 |
| `DS23XMLStr` | string | URI 编码的 XML；结构见下文 |
| `convertType` | string | 本次卖家配送→亚马逊配送提交为 `"2"` |
| `language` | string | 当前外页语言上下文 |

XML 层级已观察到：

```text
ROOT
└─ DS23
   ├─ DS2301
   ├─ DS2302
   ├─ DS2304
   └─ DS2307
```

| XML 键 | 本次可确认值/关联 | 仍不能推断的内容 |
|---|---|---|
| `DS2301` | 父商品内部 ID；与广告详情同目标行的 `DS2301`、`DS0406` 同值 | 不保存原 ID；不能与子 SKU 文本混用 |
| `DS2302` | 子变体内部 ID；与广告详情同目标行的 `DS2302`、`DS0407` 同值 | 不保存原 ID；读取请求中 `DS2302_t` 仍待单独同值校验 |
| `DS2304` | 本次转换提交值为 `2` | 只确认本次卖家→FBA 流程，不宣称完整枚举表 |
| `DS2307` | 值与转换后界面 FNSKU 一致 | 不保存原值；不因此推断生成算法或全部唯一性规则 |

实际保存 XML 未出现 `Battery`、`Hazmat` 之类独立危险品字段；不能把危险品表单的 UI 状态擅自对应到以上编号字段。

本轮后续广告组详情已做同一目标行的实际值交叉核对：`DS2312` 对应界面子 SKU、`DS2303` 对应界面 ASIN，`DS2301=DS0406` 对应父商品 ID，`DS2302=DS0407` 对应子变体内部 ID；后两者分别与本次 FBA 提交的 `DS2301/DS2302` 相等。这是本样本的实值关联证据，不是按字段编号猜测。原始标识及商品原文不保存。

## 4. 危险品信息分支

- 已实际切换表单中的“是 / 否 / 不确定”选项。本次观察窗口内没有新增 POST，也未出现额外输入字段。
- 最终采用“否 / 否”提交，观察到的新增网络活动仅为打勾图片的 GET；主表危险品状态变成“已完成”。
- 这说明本次**未观察到独立危险品保存 POST**，不等于证明该平台在所有选择、所有商品或所有版本都没有危险品写入请求。
- 页面“已完成”是本次 UI 状态证据；不能替换为不存在的业务 Code=0。主保存 XML 中也未见独立危险品字段，因此**不能声称后端已经独立持久保存危险品问卷**，更不能凭流程先后猜测其字段映射。

## 5. 回读与成功判据

转换后 `GetSellerProductList` 返回 HTTP 200、Code=0；页面中同一子 SKU 显示 FNSKU、FBA 配送状态和“转换为卖家配送”入口，可售 0。这些是**后置状态已改变**的直接证据。

“可售 0”不代表转换失败，也不代表已经完成 FBA 入库、货件、补货或广告资格校验；这些是后续独立链路。保存按钮点击、HTTP 200、页面跳转中的任一项，单独都不足以证明转换成功。本轮结论依赖同一对象的后置回读。
