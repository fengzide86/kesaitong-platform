# V2 配送模板价格分段现场证据（2026-10-04）

## 结论与范围

本轮新建一次性模拟模板 `KST_API_PRICE_BAND_20261004`，选择按价格分段模式，完成填写、保存、重新打开详情回读和删除。模板数 **5 → 6 → 5**，原 `Smart_Precise_V34_0.5kg` 默认模板保持不变；该测试模板从未设为默认，也未绑定商品，删除后没有重建。

已经捕获非空 `DS08AXml` 的真实提交及对应详情结构。关键差异是：**请求中的 `DS08A06` 使用页面规则序号，响应中的 `DS08A06` 使用持久化规则 ID**。不能把请求序号当作可跨页面复用的服务器规则 ID。

本文件只保存字段名、类型、测试名称、匿名关联与事件序号，不保存模板、规则或账户的原始 ID。事件属于恢复后新 IAB 采集段，与 [商品模板绑定补证](product-template-binding-2026-10-04.md) 同段；不能与较早标签页中的相同序号混用。此样本证明价格分段路径已执行，不代表所有边界、计费结果或校验分支均已覆盖。

## 2. SaveTemplate 请求编码

外层为 URL 编码表单，`arrayStr` 是 JSON 数组字符串。数组本轮含一个对象，以下字段解析后均为 **string**：

```text
courseId
shopId
DS0701
DS0705
DS0708
DS08Xml
DS08AXml
language
```

`DS0705` 为模板名称，`DS0708="1"` 为本轮选择的价格分段模式；详情 `jsonStr1[].DS0708` 返回 number 1。重量/件数模式此前为 `"0"`，见 [配送模板主文档](template-api-evidence-2026-10-04.md)。

`DS08Xml` 和 `DS08AXml` 为 URI 编码 XML 字符串，解码后分别包含：

```text
ROOT
└─ DS08（本样本 7 条规则）

ROOT
└─ DS08A（本样本 8 条价格分段）
   ├─ DS08A05  配送服务 code
   ├─ DS08A06  请求中为页面规则序号
   ├─ DS08A09  区间起点
   ├─ DS08A10  区间终点，末段可为空
   └─ DS08A11  本段费用
```

XML 节点值在请求中均为文本。下面的数值表示字段内容，不意味着 XML 传输了 JSON number。

## 3. 已执行的两段规则

目标规则地区为 Alaska/Hawaii/Puerto Rico，服务 code 为 `10001`（标准配送）。对应 `DS08` 规则的 `DS0817="2"`，两条 `DS08A` 请求均以 `DS08A06="2"` 关联到该页面规则。

| 请求分段 | DS08A05 | DS08A06 | DS08A09 | DS08A10 | DS08A11 |
|---|---|---|---|---|---|
| 首段 | `"10001"` | `"2"` | `"0.00"` | `"10"` | `"2.5"` |
| 后续末段 | `"10001"` | `"2"` | `"10.01"` | 空文本 | `"1.5"` |

其余 6 条配送规则各保留一条默认分段：起点 `"0.00"`、终点空文本、费用 `"0.00"`，合计 8 条分段。默认分段只说明表单随本次请求提交的数据，不说明已验证这些规则的实际计费结果。

首段终点输入 10 并按 Tab 后，页面自动生成下一段起点 10.01。只确认本样本的生成行为，未验证任意精度、舍入规则、负值或不同币种的步长。

价格分段模式下，`DS08` 的 `DS0814`、`DS0815`、`DS0816` 在请求 XML 中为空，详情响应对应值为 null。不能继续把此模式下的空值解读成重量/件数模式中的每单费、单位价与单位选择。

## 4. 详情回读与规则关联

`GetFeightRelationList` 外层表单字段为 `courseId, shopId, ds0701, language`，线格式为文本。响应外层的 `result`、`jsonStr1`、`jsonStr2`、`jsonStr3` 是需再次解析的 JSON 字符串。

| 解析后的数据块 | 本轮样本 | 关键事实 |
|---|---|---|
| `jsonStr1` | 1 个模板 | `DS0708:number=1`，确认价格分段模式 |
| `jsonStr2` | 7 条规则 | `DS0801` 为规则 ID；目标行 `DS0817:number=2`，仍是规则序号；`DS0814/DS0815/DS0816:null` |
| `jsonStr3` | 8 条分段 | 两条目标分段分别读回 0→10、10.01→无上限，以及 2.5、1.5 费用；分段 ID 值不落盘 |

`jsonStr3` 元素的已观察类型：

```text
DS08A01 … DS08A07: number
DS08A08: string
DS08A09: number
DS08A10: number | null
DS08A11: number
```

其中 `DS08A10` 对本轮首段为 number 10，对末段为 null；`DS08A09` 和 `DS08A11` 分别对应起点及费用。未核对语义的其他 A 字段只登记名称与类型，不从编号推断含义。

本轮已逐值核对以下关联，未保存实际规则 ID：

| 层次 | 关联方式 | 已确认边界 |
|---|---|---|
| 提交 XML | `DS08A06="2"` 对应 `DS08.DS0817="2"` | 页面规则序号关联 |
| 详情响应 | `jsonStr3[].DS08A06 === 对应 jsonStr2[].DS0801` | 持久化规则 ID 关联；不再是页面序号 2 |
| 同一详情规则 | `jsonStr2[].DS0817 === 2` | 序号仍单独保留，不能与 `DS0801` 混用 |

因此后续脚本需要根据其正在处理的是页面提交模型还是服务器回读模型来解释 `DS08A06`，不能统一写成“始终为规则序号”或“始终为数据库 ID”。

## 5. 控件与校验的异常观察

### 地址复选框与提交值不一致

本轮将“邮政信箱”复选框取消勾选，可见状态为 false，但提交的 `DS0811`、`DS0812` 仍均为 `"1"`；重新打开后仍显示街道地址与邮政信箱。**没有完成地址类型开关的可靠字段映射，也不能称邮政信箱配置已成功关闭。**

此现象只证明当前操作中控件状态与持久化结果不一致，不能据此断言前端实现或服务器忽略字段的原因。后续应同时比较控件、实际 XML 与详情回读，不仅检查 checkbox 的 visible/checked 状态。

### 价格范围提示不等于最终未保存

输入过程中出现提示：

> 输入的价格必须高于之前的价格范围中的价格。请再次输入其他价格或修改之前的价格范围！

关闭提示后，页面保留上述两段，后续实际保存返回 Code=0，详情也读回同两段。本轮不能将该提示写成“所有情况下都会阻断保存”，也不能反向推断所有价格区间都可保存。提示触发时机和其他错误输入组合仍待单独验证。
