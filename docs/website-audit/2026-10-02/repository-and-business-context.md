# 仓库、商业计划与现有网站代码

## 产品与商业验证

商业计划把产品定位为亚马逊赛训/实训效率工具，后续扩展速卖通：

- C 端：个人工具箱；B 端：批量工作台；内部运营端：授权、设备、席位、订单、客服、知识库和批次管理。
- 价格、市场规模、分润和 SOP 都是验证假设。v2 计划用 90 天小规模受控验证确认真实付费、授权安装、首次使用、成功/失败/人工介入、退款流失和单位交付成本。
- 现有系统测试、Demo 和 Runner 底座不能证明外部平台真实脚本已经完成，也不能把 Demo 成功当作真实成交或生产验收。

## 赛训打法资料

资料链路是：选品/商品资料 → 物流模板 → 商品发布与变体 → 自发货/FBA → 营销。营销资料拆成商品推广、品牌推广、A+、秒杀、优惠券、Prime 折扣、管理促销七条工作流，标识和前置条件不同。

资料包已完成归档、校验和两轮阅读。5 份 PDF 共 41 页，其中 35 页可读；营销 PDF 第 14–19 页的图片对象损坏，不能自行补写。资料中的“高分”“最便宜”等表述仍需现场验证。

## 仓库内“官网”与外部云端软件不是同一个东西

仓库的 `src/marketing` 是独立宣传官网，只包含：

- `/` 首页：产品价值、受众、工作流、FAQ、个人工具/团队批次场景切换、桌面下载和咨询弹窗；
- `/terms`（兼容 `/user/terms`）条款；
- 通配 404。

它没有 C/B/Admin 工作台、外部云端登录、Runner 或业务 API；完整应用路由在 `src/router/index.ts`，与宣传官网分开。后续采集外部 bjysoft 页面时，不能把仓库官网路由当成目标平台页面。
