## 证据范围

本次在用户手动重新登录后，沿用同一个 Amazon 仿真浏览器会话，只读打开 `SellerStockFBAList`，选择一条已有的“即将发货”货件进入 `SellerProductFBAStep2`。没有创建货件、修改箱子、删除货件、打印标签、完成货件或确认发货；所有商品标识、货件编号、追踪号、地址和账号信息均不写入本文。

这份记录补充的是**页面结构、状态依赖和脚本端点线索**。本次只读补证没有同步采集 Network 请求/响应，不是新的 HTTP 或业务结果证据；既有历史实测结果仍以 `v2-api-catalog-2026-10-03.md`、`v2-event-traces-2026-10-03.md` 和专项证据文件的原采集批次为准。

## 2. 货件详情页结构

- 路由：`/ECrossAmazon/SellerProductFBAStep2`。
- 页面显示的步骤导航：设置数量 → 预处理商品 → 为商品贴标 → 检查货件 → 预处理货件 → 一览。导航名称存在不等于对应步骤已成功进入或执行。

- 本次观察到同一页面的两个只读内容分区；是否伴随请求不由页面切换现象推断：
  - **货件内商品**：MSKU、标题、状况、已发货、已收到，并同时展示 ASIN/FNSKU/内部商品号等关联标识；本文不保留具体值。
  - **追踪货件**：箱号、追踪编码、承运人状态、重量（lb.）、尺寸（in.）。
- 当前详情可见的动作：返回、返回“货件处理进度”、处理另一个货件。预渲染 DOM/页面脚本另有检查并修改商品、隐藏商品、确认、确认自动生成、打印标签、打印箱子标签、完成货件、删除货件等控件线索；这些线索不证明控件当前可见、启用或已经点击。

### 3.1 货件商品修改 XML

页面脚本把货件商品变更序列化为 URI 编码 XML，字段名为：

```text
ROOT/Product/
  DS2001       父商品上下文
  DS2302       子变体上下文
  DS75S05      货件内商品行上下文
  DS75S11      该行数量/标签数量
```

### 3.2 箱子重量与尺寸 XML

箱子修改序列化为：

```text
ROOT/ProductBox/
  DS7519       箱子重量
  DS7520       箱子长度
  DS7521       箱子宽度
  DS7522       箱子高度
```

脚本把两段 XML 分别放入 `DS23XMLStr` 和 `DS75XMLStr`，并通过 `optype` 区分修改商品数量、删除商品、修改箱子重量/尺寸和删除货件。字段语义目前只达到页面脚本使用层级；业务枚举、单位边界和后端错误码仍需要真实写入抓包确认。

还不能直接声称“可无人值守完成 FBA 货件”：

1. `CreateFBAPlanShipmentInfo`、`SureFBAPlanShipmentInfo`、`SaveFBAPlanShipmentInfo`、`CompleteFBAPlanShipmentInfo` 的真实请求/响应体和业务 Code/Msg 仍需用专门测试对象抓取。

4. 账号再次出现“登录失效”时，必须回到入口手动恢复单一会话后再采集；不能把 HTTP 200 或空列表当成正常业务结果。
