## 2. 商品发布素材与字段文件

`发品(3)\发品` 下存在 36 份可解析 JSON 文本（包含重复副本），对应 24 个唯一的非空 `ALE-######` 商品代码；这是该子目录口径。总资料目录另有 1 份可解析但没有商品 ID 的空模板，不能把它计入“已填商品”。字段可分为：

- **发布主键/素材**：商品代码、变体主题、图片路径、旧/新图片文件名。
- **基本商品属性**：外部商品 ID、ID 类型、标题、品牌、制造商、零件号、尺寸/颜色、商品分类相关字段。
- **销售与库存**：标准价、划线价、促销价与起止时间、数量、最大订购量、备货/配送时效、补货日期。
- **履约与配送**：配送组、MFN/AFN 标记、商品重量与单位、发货模板引用。
- **合规/危险品**：电池、锂电池、危险品规则、SDS、闪点等字段；大量商品为空是正常的“按品类条件字段”，不能因此推断当前页面缺失。
- **描述与搜索**：五点描述、长描述、关键词、受众/场景/风格等分类字段，键名带有平台内部字段编号。

抽样 JSON 可正常解析，核心价格、数量、重量、标题、外部 ID 等字段在 36 份文件中都有值；尺寸、颜色、MFN/AFN、税码、电池等字段只在部分商品出现。该差异符合按类目显示条件字段的模式，但是否计分必须通过当前 V2 页面/接口或规则手册确认。

补充统计：37 个可解析文件（含 1 个空模板）都出现 `item_name`、`standard_price`、`quantity`、`external_product_id`、`merchant_shipping_group_name`、`item_weight`、单位和 `fulfillment_latency` 键，但空模板对应值为空；`item_sku` 在 37 个文件中均为空，不能把它当成动态变体 SKU。MFN/AFN 只在部分商品 JSON 出现；`color_name`、`size_name` 也按类目条件出现，空值不等于页面字段缺失。

嵌套目录 `提分的品\商品上架代码（复制＋粘贴）(1)(1).txt` 是可读的 V28 页面字段复制/粘贴辅助脚本（351 行），固定引用 `j-select-proNo`、`variation_theme`、`msterpicpath`、`proOldName`、`proNewName` 以及六个属性页签（基本信息、报价、合规、描述、关键词、更多详情）。它明确移除了动态变体，只做字段复制/粘贴和页面回填，不点保存/提交、不发网络请求；不能代表当前 V2 DOM 仍使用相同 ID。根目录同名文件、`AGL填信息代码.txt` 及三个顶层 HTML 是二进制/不可按普通文本解码，不能把随机字符串命中当作已同步逻辑。

已在当前已登录 V2 库存列表只读观察到两条商品记录，其中一条商品代码与上述本地素材清单相符。由此可以确认：本地素材中的商品代码可用于“当前库存记录 → 本地发布资料”的对照索引；但不应把本地标题、价格、图片或评分直接批量写回平台。

## 4. 补货与网络线索

`补货脚本.txt` 为旧站 Tampermonkey 脚本，拦截旧主机的 `GetOrderList` 与 `GetStockList` 数据，在浏览器 `localStorage` 中建立订单/库存映射，并计算建议补货数量。它是**只读计算辅助**，不等于当前 V2 的补货接口；旧主机与当前 V2 主机不同，不能直接注入或复用。

旧 Python 脚本没有独立 HTTP 客户端，主要通过 Selenium 导航、iframe、页面按钮与页面 XHR 产生网络请求。静态可确认的页面/动作线索包括：

- 商品/库存读取：库存列表、商品代码/ASIN/价格读取。
- 广告与促销：广告活动、秒杀、优惠券、Prime 折扣、促销创建页面；P1–P5 分支均含提交按钮。
- 物流模板：配送设置、服务类型、国家选择、重量/价格阶梯、模板保存。
- 订单/仓库：订单列表、国内仓库 iframe、分拣、打包、物流填写、最终发货确认。

这些线索已在 `legacy-script-reference-2026-10-03.md` 和 `network-observations-2026-10-03.md` 中与当前 V2 现场观察分开记录。旧脚本引用旧主机和旧选择器，必须在当前 V2 页面重新定位；不能通过“脚本跑起来”证明当前规则或评分点成立。
