# V2 现场采集并行与串行执行矩阵（2026-10-03）

本文件只用于安排现场取证，不等于允许批量运营或无人值守执行。当前账号为单账号、单电脑、单登录上下文；“并行”优先指静态资料整理、独立只读页面准备和记录工作并行，不能把多个登录会话或多个写入请求同时发给平台。

## 1. 并行边界

| 级别 | 可做什么 | 约束 |
| --- | --- | --- |
| P0 静态并行 | 旧脚本逐行核对、现有审计文档整理、页面字段目录、请求字段脱敏 | 不打开平台写入页面，不发送接口请求 |
| P1 只读并行 | 同一正确亚马逊会话中分别打开库存/FBA、广告只读列表、配送只读列表、订单/仓库只读页面 | 共享一个浏览器会话；每页使用独立证据游标；禁止同时提交、删除、确认发货；若出现“账号已在其它地方登录”立即停止并从 Welcome6→亚马逊仿真恢复 |
| S1 对象级串行 | 同一商品、模板、广告、促销、优惠券、Prime 或订单的读取→写入→回读 | 必须等待业务回读完成后再进入下一步；不可把 HTTP 200 当成功 |
| S2 破坏/不可逆串行 | 删除规则、设默认模板、发货、确认发货、FBA 发送库存、取消/结束活动 | 单一明确测试对象、保存前快照、停止条件和回滚方式；默认不执行 |

## 2. 页面/链路矩阵

| 链路 | 首批可并行只读项 | 必须串行的步骤 | 写入对象与风险 |
| --- | --- | --- | --- |
| 商品/库存 | `SellerProductCategory`、`SellerProductList`、FBA 筛选、商品详情、FBA 货件列表/既有货件详情 | 选类目→创建/编辑→图片→`SaveProduct`→列表/详情回读；商品→FBA 转换→危险品→FBA 库存回读 | 商品内容可能影响库存与广告候选；同一商品不要并行编辑/转换 |
| FBA 转换 | 普通库存、亚马逊配送筛选、FBA 库存、货件/按 SKU 查询、既有货件详情 | 读取目标行→选择“只转换”→危险品表单→保存并继续→FBA SKU/ASIN/FNSKU 回读→再进入广告/Prime | `只转换` 已可受控验证；“转换并发送库存”、设置数量、预处理、贴标、取消货件属于高风险 S2 |
| 配送模板 | `GetTemplateList`、`GetFeightBasicsList`、`GetFeightRelationList`、国家/服务/重量字段只读 | 新建→规则→`SaveTemplate`→模板/规则关系回读；编辑/默认/SKU 分配各自回读；删除最后单独执行 | 删除既有国际规则、设默认模板、SKU 分配会改变后续订单可用渠道；必须测试模板、快照和回滚 |
| 商品推广 | 广告列表、候选商品列表、FBA 视图中的 SKU/ASIN 映射、创建表单字段 | FBA 行确认→`GetProductSKUList`→精确选择 ASIN/SKU→`SaveAdvertisingActivity`→活动/广告组明细回读→再做编辑/暂停/取消 | 同一活动禁止重复提交；预算、日期和投放状态为真实业务写入；先使用短周期、低预算测试活动 |
| 秒杀 | 秒杀列表、ASIN 搜索、资格提示、推荐结果 | 搜索→确认出现推荐→高级编辑→提交→列表/状态回读；无推荐立即停止 | 当前账号无推荐，不能猜隐藏字段或强行提交；推荐出现后仍需单对象、短时段、回读 |
| 优惠券 | 列表、创建四步表单、ASIN 候选、目标买家与限制字段 | 搜索→预算/折扣/日期→预览→提交→列表/详情回读→编辑/取消只读回归 | 已有测试记录不要重复创建；取消/删除可能不可逆，需单独确认 |
| Prime | 列表、SKU 候选、资格提示、验证结果 | FBA SKU 回读→填写 SKU/折扣→验证→保存→列表“等待中”回读→编辑/结束 | 卖家自配送 SKU 不可混用；“等待中”不等于成绩/订单成功；结束/取消串行 |
| 购买折扣/促销 | 列表、创建表单、类型/日期/商品范围字段 | 读取类型→填写→保存→列表/详情回读；编辑→回读；取消/删除最后 | `DS1509`、`internalDescription`、`trackingId` 语义仍需请求证据；买一赠一单独分支，不能与普通促销并行 |
| 订单/仓库 | 订单状态计数、订单列表、订单详情、国内库存、运输/出入库/分拣/打包/立即发货/发货记录的只读页面 | 单订单：订单详情/重量/国家→库存确认→分拣→打包→承运人→运单号→立即发货→卖家确认发货→订单/发货记录回读 | 发货链是不可逆 S2；当前没有明确测试订单和回滚方式，不执行。不同订单即使理论上可并行，也受单账号/同库存约束，默认串行 |
| FBA 货件 | 货件列表、详情、一览/货件内商品/追踪货件只读分区 | 读取计划→设置数量→预处理→贴标→检查→发送/取消→状态回读 | 发送库存、取消货件、修改数量是高风险 S2；不能把已有货件详情当作可重复测试对象 |

## 3. 推荐执行顺序

1. **会话基线**：关闭失效旧标签，只保留 `/User/loginPage24`→亚马逊仿真会话；记录会话时间和当前页面。若出现“账号已在其它地方登录”，停止所有并行页，重新从 Welcome6 进入。
2. **P0 静态并行**：同时整理旧脚本、字段映射、已知 API 目录和缺口；不触碰现场状态。
3. **P1 只读分组**：按“库存/FBA”“广告/促销”“配送模板”“订单/仓库”四组逐组打开并记录页面、网络和空/错状态。每组内部可并行准备记录，但浏览器请求保持可追踪，避免多标签抢占上下文。
4. **S1 已有受控对象回归**：只对现有已知记录做读取和详情回读，不重复创建；先确认对象 ID/名称，再进入对应编辑或停止的只读入口。
5. **S1 新写入实验**：每条主线只创建一个带 `KST-AUDIT-日期-序号` 的测试对象，提交后立即列表/详情回读，并保存业务 `Code/Msg`、状态和回读字段。
6. **S2 高风险动作**：FBA 发送库存、模板删除/默认、仓库分拣/打包/发货、订单确认、活动取消/删除只在明确指定对象和回滚条件后单独执行；一次只做一个动作，完成回读后再决定下一步。
7. **证据收口**：每条链路输出 `page→trigger→method/path→request_keys→HTTP→Code/Msg→next_state→readback→write/evidence`，去除 Cookie、Token、密码、完整 `paras`、订单原文和商品原文。

## 4. 网络记录优先级

- **必须记录**：业务读写 XHR/fetch 的 method、脱敏 path、字段名/类型、HTTP 状态、业务 Code/Msg、下一状态和回读请求。
- **应记录**：页面壳 GET、iframe 页面入口、登录失效接口、分页/筛选请求、空列表和权限错误响应。
- **低优先级**：图片、字体、静态 JS/CSS、遥测、重复 SignalR 心跳；只在解释页面加载失败时保留。
- **禁止落盘**：完整 `paras`、Authorization/Bearer/Cookie、密码/验证码、客户地址电话、订单和商品原文。

## 5. 交付判断

- 只有 P1 只读与 S1 受控写入完成并回读，才可把该链路标为“脚本原型可接入”。
- 任何缺少真实写入请求字段、业务返回或回读的链路，标记为“证据不足”，不直接生成无人值守脚本。
- 仓库发货、FBA 发送库存、模板删除/默认和活动取消/删除即使按钮可点击，也不能在没有回滚条件时标记为完成。
