# V2 并行执行补充说明（2026-10-04）

本说明补充 `parallel-execution-matrix-2026-10-03.md`，对应当前“希望所有链路一起推进”的安排。它不扩大账号授权，不改变单账号、单电脑、单浏览器会话约束，也不把多个真实写入请求并发发送给平台。

## 1. 可以并行推进的工作

| 并行组 | 内容 | 证据/产出 |
|---|---|---|
| A 静态整理 | 旧脚本字段逐行核对、页面目录、已有 API 证据去重、请求字段脱敏 | 不触碰平台，不产生业务状态 |
| B 文档审计 | FBA/模板/广告/活动/订单各专项的缺口核对、事件序号交叉检查、交付包清单更新 | 只读文件变更，可与现场采集并行 |
| C 只读准备 | 准备 FBA、模板、广告、活动、订单页面的定位器和脱敏记录模板 | 不提交、不删除、不确认发货 |
| D 证据收口 | 对已经取得的 HTTP/Code/回读结果做一致性检查，标记“已确认/待确认/未取得” | 不重放已成功动作 |

## 2. 仍需同一会话串行的现场工作

同一账号只能保持一个有效登录上下文。可以轮换页面，但不能让多个标签同时提交或让多个采集者共享同一 Network 游标。

| 链路 | 当前状态 | 下一步真实工作 | 串行原因 |
|---|---|---|---|
| FBA 货件/入库 | 列表与入库计划已取得 Code0 空数组；货件写入接口目前只有静态脚本线索 | 先出现可用测试货件，再抓创建/确认/箱子/承运人/完成及回读 | 需要同一货件 ID、同一前后状态，不能并发改数量和状态 |
| FBA 转换/危险品 | 子 SKU 转换及 FBA/FNSKU 回读已确认；`SaveDeliveryWay` 正文缺失 | 仅在新测试对象可用时补响应正文、危险品独立持久化和失败分支 | 不重复提交已转换对象，避免状态反转 |
| 配送模板 | 创建/编辑/默认/恢复/删除、价格分段、单商品绑定已确认 | 逐子 SKU/批量绑定、单位/限重/币种/处理时间边界、失败分支 | 模板默认和商品引用会影响后续订单 |
| 商品推广 | 候选、SKU/ASIN 精确关联、广告组编辑和回读已确认 | 时区/跨日、竞价/投放方式、暂停/取消/删除及失败分支 | 同一活动不能重复提交，且需保存后详情回读 |
| 秒杀/优惠券/Prime/购买折扣 | 各有成功或部分成功样本；多项写入正文缺失 | 逐类型补写入响应、状态变化、时间边界、失败和取消/删除合法入口 | 活动状态与商品关联有先后依赖 |
| 国内仓库/订单 | 分拣→打包→仓库发货→卖家确认成功链已闭环 | 多商品/多包裹、缺货/承运人不可达/重复提交、跨会话恢复 | 发货不可逆，不能拿同一订单做并发异常实验 |

## 3. 建议的并行编排

1. **静态并行**：A、B、D 立即并行，由不同工作单元检查文件和现有事件；不打开平台写入页。
2. **现场只读轮换**：由一个浏览器会话所有者依次采集 FBA、模板、广告、活动、订单页面；其他工作单元只准备字段表和脱敏模板。每个动作独立记录 Network 游标，动作后立即分批读完事件。
3. **对象级写入**：每条链路最多保留一个一次性测试对象；提交后必须完成列表/详情回读，再把结果交给文档工作单元。不同链路可在“前置准备”阶段并行，但真实写入仍按对象串行。
4. **高风险动作**：FBA 完成/发送库存、模板默认/删除、活动取消/删除、订单确认发货只能一个动作一个对象；即使用户已授权，也不把它们并发化。

## 4. 当前不应重复的已完成动作

- 不重复已成功订单的分拣、打包、仓库发货和卖家确认。
- 不重复已删除的测试配送模板、价格分段模板和购买折扣测试对象。
- 不重复已完成的 FBA 子 SKU 转换，不用反向转换制造“响应正文”样本。
- 不操作原有广告、优惠券、Prime、促销对象；新对象才可做独立补证。

## 5. 现场阻塞与恢复

- FBA 列表/入库计划的 Code0 空数组是当前上下文事实，不等于接口失败，也不等于有可写货件。
- 登录失效或账号冲突时，停止全部现场并行页，从 `Welcome6 → 亚马逊仿真 /24` 恢复单一会话；不复制 Cookie、Token 或完整 `paras`。
- 发生空列表时先检查业务 `Code/Msg` 和 Network 回读，再判断对象确实为空；不能用首屏 0 行或 HTTP 200 代替业务结果。

## 6. 交付判据

只有同时具备“真实请求字段、HTTP 状态、业务 Code/Msg、后置列表/详情回读”的链路，才标记为可进入脚本原型。缺少写入正文或异常分支的链路继续标记为“部分证据”，不在脚本中假设成功。
