# 商品推广 API 增量证据（2026-10-04）

## 范围与结论

本轮在当前 V2 亚马逊仿真会话中，沿用已有 KST 测试广告活动和广告组，补采候选搜索、商品选择、默认竞价编辑、真实保存及广告组列表回读。没有新建第二条同类广告活动，不操作真实 Amazon 广告。

已确认的变化：广告组已选商品由 **1 个变为 2 个**，默认竞价由 **$0.53 变为 $0.54**；保存请求返回 HTTP 200 / Code 0，随后广告组列表和详情回读均确认变化。候选商品、广告组详情与本轮 FBA 写入中的父商品/子变体 ID 已按同值交叉核对，不只依赖商品名称或列表位置。

这只证明本样本的编辑保存成功分支。活动每日预算保留 $10，日期保留原值；本轮未确认日期时区，不能据此声称时区、所有投放方式、所有竞价策略或全部异常分支已经验证。

## 脱敏与证据口径

- 活动、广告组与商品分别用 `ad-activity-existing-01`、`ad-group-existing-01`、`ad-product-01/02` 指代，不落盘原始 SKU、ASIN、内部 ID、完整 paras、Cookie、Token 或账号凭据。
- 事件序号为本次浏览器 CDP 会话内的请求/响应定位标记，不能作为跨会话业务标识。
- HTTP 200 与业务成功分开判断；保存后还要回读持久化列表或详情。按钮点击、页面输入框变化均不单独算业务成功。
- 请求字段仅以本轮实际捕获为依据。旧脚本控件名和历史文档字段不能自动升级为本轮已验证请求字段。

## 1. 候选商品与搜索

实际候选接口为 `POST /ECrossAmazon/GetProductSKUList`。

| 动作 | 本轮观察 | 请求 → 响应序号 | 证据边界 |
|---|---|---|---|
| 打开既有测试广告组编辑页，读取全部候选 | HTTP 200 / Code 0；9 个候选商品 | `6529 → 6533` | 仅为本账号本次编辑上下文，不代表平台全局商品总量 |
| 用当前库存中读取的 SKU 搜索 | HTTP 200 / Code 0；1 个候选 | `6576 → 6584` | 搜索使用真实页面值；文档不保存其原文 |
| 用同一商品的 ASIN 搜索 | HTTP 200 / Code 0；1 个候选 | `6588 → 6591` | 已与后续详情按父商品/子变体 ID 交叉核对 |
| 保留原商品并加入候选商品 | 已选商品数 1 → 2 | 保存见下一节 | 后续保存、广告组列表及详情回读均为 2 个商品 |

本轮有商品候选可用，不能再沿用历史“搜索返回 0 商品”的状态作为当前阻塞。历史空结果仍只是对应旧会话/旧条件的观察，不据此推断永久无资格。

## 3. 请求与返回字段

下面的类型是本轮实际值解码后的类型，不是平台公布的服务端类型契约。form 字段在线上仍为文本；`arrayStr` 为字符串形式的 JSON 数组，本轮均包含 1 个对象。返回的 `result`、`jsonStr` 系列字段也是 JSON 字符串，需要二次解析。

### 3.1 候选读取 GetProductSKUList

请求 `arrayStr[0]`：

- `courseId, shopId, keyword:string`
- `optype:number`

返回 `result` 解码为成功结果，`Code=0`、`Msg=null`；`jsonStr` 解码为数组，全部候选/SKU 搜索/ASIN 搜索分别为 9/1/1 行。每行字段：

| 实际类型 | 字段 |
|---|---|
| number | `DS2301, DS2302, DS2305, DS2306, DS2316` |
| string | `DS2303, DS2309, DS2310, DS2312, DS2320, DS2326, DS2327, DS2024, DS2048` |
| null | `DS2317` |

### 3.2 保存 SaveAdvertisingActivity

请求 `arrayStr[0]`：

| 实际类型 | 字段 |
|---|---|
| string | `courseId, shopId, actionType, ds0301, ds03S01, DS03XmlStr, DS04XmlStr, DS05XmlStr, DS05XmlStr_2, language` |
| number | `optype` |

本样本为广告组编辑：`actionType="1"`、`optype=1`。这只是本次操作组合，不据此推断其他创建、删除、暂停等操作值。

XML 字符串需要 **URI 解码后再解析**：

| 字段 | 解码后的结构 | 本轮字段/数量 |
|---|---|---|
| `DS03XmlStr` | `ROOT/DS03_amz`，1 个 `DS03_amz` 节点 | 子键见下方；其中若干键在同一节点内重复 |
| `DS04XmlStr` | `ROOT/DS04_amz`，2 个商品节点 | 每行 `DS0406, DS0407, DS0409, DS0410` |
| `DS05XmlStr` | `<ROOT></ROOT>` | 本次为空，不等于其他分支永远为空 |
| `DS05XmlStr_2` | `<ROOT></ROOT>` | 本次为空，不推断其完整字段结构 |

`DS03_amz` 的唯一子键集合为：

```text
DS03S13, DS0311, DS0323, DS03S05, DS03S12, DS03S22,
DS03S14, DS03S16, DS03S18, DS03S20,
DS03S15, DS03S17, DS03S19, DS03S21,
DS0324, DS0325, DS0326,
DS0304, DS0305, DS0306, DS0307, DS0308, DS0309, DS0310
```

**重复节点必须保留：** `DS0311, DS0323, DS03S05, DS03S12, DS03S22, DS03S14, DS03S16, DS03S18, DS03S20` 在本次 `DS03_amz` 中重复出现。上面的“唯一子键集合”只用于字段目录，不能当作可重放请求。后续解析应保留 XML 节点原顺序与多值，不得转为单值字典后静默覆盖/去重；本轮没有验证服务端遇到重复键时取首项还是末项。

保存响应外层 `result:string`，解码后为：

```text
Code:number = 0
Msg:string = "操作成功."
RedirectUrl:null
Token:null
```

此响应本身没有在本文件中证明返回新的活动/广告组 ID；本轮沿用既有对象，再通过列表与详情回读确认保存结果。

### 3.3 广告组列表 GetAdvertisingActivityGroupListOrDetail

实际接口：`POST /ECrossAmazon/GetAdvertisingActivityGroupListOrDetail`。

请求为 form：`courseId, shopId, ds0301, ds03S01` 为数字形态文本，`keyword` 为文本。响应 `result` 解码 `Code=0`；`jsonStr` 解码数组 1 行：

| 实际类型 | 字段 |
|---|---|
| number | `DS03S01, DS03S04, DS03S06, DS03S08, DS03S09, DS03S13, DS03S14, DS03S15, DS03S22` |
| string | `DS03S05` |
| null | `DS03S07` |

保存前页面回读为已安排、$0.53、1 个商品；保存后列表回读为 $0.54、2 个商品。状态文案不等于实际投放效果或计费结果。

### 3.4 广告组详情 GetAdvertisingActivityGroupDetail

请求 `arrayStr[0]` 中 `courseId, shopId, ds03S01, keyword_p, keyword_k` 均为字符串。

返回外层含 `result` 及 `jsonStr1`–`jsonStr4` 字符串；`result` 解码为 `Code=0, Msg=null`。各明细解码后：

| 返回字段 | 解码后数组 | 行字段类型 |
|---|---|---|
| `jsonStr1` | 1 行广告组配置 | `DS03S05:string`；`DS03S12` 至 `DS03S22:number`，其中 `DS03S13=0.54` |
| `jsonStr2` | 2 行商品明细 | `DS0401` 至 `DS0410:number`；`DS0411` 至 `DS0414:null`；`DS2024, DS2048, DS2303, DS2312:string`；`DS2301, DS2302, DS2305, DS2306:number` |
| `jsonStr3` | 空数组 | 无行，不能推断完整行结构 |
| `jsonStr4` | 空数组 | 无行，不能推断完整行结构 |

## 4. 已确认的字段与精确关联

下表来自本轮页面展示值、候选响应、保存 XML 与详情响应的**同值交叉核对**，不是按字段编号猜测：

| 语义 | 已确认字段/关系 | 使用边界 |
|---|---|---|
| 默认竞价 | 广告组配置 `DS03S13` | 本轮编辑后详情为 `0.54`，与列表 `$0.54` 一致 |
| 子 SKU | `DS2312` | 与界面实际子 SKU 相同；不与父 SKU 混用 |
| ASIN | `DS2303` | 与同一行界面 ASIN 相同；SKU 搜索与 ASIN 搜索都定位该候选 |
| 父商品内部 ID | `DS2301 = DS0406` | 候选/详情中的 `DS2301` 与写入商品节点 `DS0406` 一致 |
| 子变体内部 ID | `DS2302 = DS0407` | 候选/详情中的 `DS2302` 与写入商品节点 `DS0407` 一致 |
| FBA 与广告关联 | 上述 `DS2301/DS2302` 与本轮 FBA 写请求相同 | 证明该商品实体的一致性，不单独证明广告资格由 FBA 转换产生 |

`DS0409/DS0410` 等已捕获但未单独验证的字段保留名称和类型，不替其编造语义。后续商品关系应以父商品 ID + 子变体 ID 和 SKU/ASIN 交叉定位，不采用“当前第一条”“名称包含”或全量 ASIN 扫描的宽松匹配。

- 已关闭本样本：候选读取/两种搜索、广告组编辑保存、商品明细回读、SKU / ASIN / 父商品 / 子变体 ID 精确关联。
- 日期时区、跨日边界、开始/结束日期校验。
- 手动/自动投放切换、竞价策略及广告位调整、否定定向等未实际改动分支。
- 暂停/取消/删除和失败/重复提交等响应结构。
- FBA 库存筛选、FBA 配送转换、广告候选选择仍是不同动作；本轮广告编辑成功不能单独证明 FBA 转换对广告资格的因果关系。
