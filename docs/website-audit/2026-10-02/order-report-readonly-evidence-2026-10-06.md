# 订单报告只读页面证据（2026-10-06）

## 1. 本轮范围

从卖家后台的“订单 → 订单报告”进入 `SellerOrderReport`，只观察页面结构、脚本线索和报告列表状态。没有点击“下载”，没有保存或修改订单，也没有记录客户订单原文。

页面路由为：

```text
/ECrossAmazon/SellerOrderReport
```

页面仍由 `AmazonSellerLayout.js`、`SellerOrderReport.js` 和卖家后台共享 CSS 承载。

## 2. 页面结构

页面标题为“订单报告”，顶部提供两个分支：

- `新订单`：今天收到的卖家自行配送订单，包含已取消或已确认配送的订单；
- `未发货订单`：截至今天仍处于待处理的订单。

页面提示订单报告可能包含客户个人信息（包括电话号码），只能用于制作货件标签。本轮没有打开下载内容。

列表列为：报告类型、批编号、请求的日期和时间、完成日期和时间、报告状态、下载。

## 3. 当前现场状态

页面初始显示一条自动订单报告记录，状态为“处理已完成”，当前账号返回“无新订单”。切换到“未发货订单”后，页面出现一条新的自动报告记录，状态为“处理已完成”，并出现“下载”链接。

这说明两个标签不是纯前端筛选：切换动作会触发报告状态读取/生成链路并刷新列表。后续采集不应反复点击，避免无必要地产生新的报告批次。

## 4. 静态脚本确认的请求边界

`SellerOrderReport.js` 中确认：

```text
POST ../ECrossAmazon/GetOrderReportList
body: arrayStr = JSON.stringify([
  { courseId, shopId, status }
])
status: 100 = 新订单；2 = 未发货订单（脚本注释将未发货描述为 3，现场调用以脚本实际初始化值为准）
```

脚本对外层 `result` 执行 `CheckResult`，再把 `jsonStr` 解析为数组。数组长度只决定下载列显示“下载”还是“无新订单”，页面表格中的批编号和时间由前端生成/格式化，不能把它们当作服务端报告正文。

下载动作另走：

```text
GET ../ECrossAmazon/SellerOrderReportDownload?paras=<加密参数>
```

本轮没有调用下载地址，也没有保存其中可能包含的客户信息。

## 5. 证据等级和边界

- 现场已见：`SellerOrderReport` 页面、两个标签、表头、完成状态和当前空订单提示。
- 静态脚本已见：`GetOrderReportList`、`SellerOrderReportDownload`、`courseId/shopId/status` 三个上下文字段。
- 尚未确认：响应正文的真实字段、下载文件格式和列、报告失败/超时/重复提交分支。
- 当前页面上的批编号、时间和账号显示值均不进入资料索引；只记录结构、状态和字段名。

## 6. 后续建议

把该页面作为“订单报表读取”操作单独登记，不与“管理订单”列表的 `GetOrderList` 合并，也不与下载后的客户数据处理混在一起。后续若要验证下载格式，应先明确单独的测试对象和脱敏存储方案；当前阶段保持不下载。
