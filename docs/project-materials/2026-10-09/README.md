# 课赛通项目资料 · 2026-10-09

这是本轮本地归类结果的团队可读副本，并补充飞书项目资料。它不是新安装包、源码合并或线上发布，也不替代各资料自己的采集日期和验收结论。

AI 接手先读仓库根目录的 [AI 接手与维护指南](../../../AI_GUIDE.md)，再看下面的专项入口。总纲与填写规则只维护在指南中；当前事实与待办只更新本目录的 `current-status.md`。本目录沿用首次同步日期，不每天新增一套“最新资料”。

## 从这里开始

1. [项目分类与工作区](./project-map.md)：官网、KST 平台、运营工作台、历史资料分别负责什么。
2. [当前工程与成果](./current-status.md)：按证据手工更新的状态与待办，保留首次盘点历史；正式基线、本地候选和未完成源码分开。
3. [旧资料与开发入口](./legacy-materials.md)：旧脚本、计算表、平台证据如何用于工具开发。
4. [图片与字段映射](./image-materials.md)：相同图片内容不等于相同上传图片位。
5. [整理结果与恢复](./organization-and-recovery.md)：已完成移动、可恢复去重和保留事项。
6. [同步范围与核验](./sync-boundary.md)：这次实际上传什么、哪些仍只在本地。
7. [飞书项目资料](./feishu/README.md)：目录、实际内容和未完成导出分别登记。

机器清单在 `manifests/`，核验通过的素材在 `materials/`。所有路径相对于本资料目录，不依赖作者电脑的盘符。

`published-files.json` 只校验本资料子目录，且排除清单自身；根目录 AI 指南、`AGENTS.md` 和工程规程的修改以本分支 Git 提交为准，不混算进素材文件数量。

## 开发接手规则

- 先确定所属产品和当前工作分支，再改源码；不要从历史 ZIP 中另建一个“最新工程”。
- 平台行为以真实按钮、请求、业务返回和回读证据为准；旧脚本只是历史逻辑来源。
- 计算规则、原始费率、表格列名和平台适配分开；V2 的表格不能直接当作 V3 恒定接口。
- 不把本地候选验收写成线上已发布，不把点击成功写成业务成功。
- 不把图片哈希去重写成业务图片位合并，不盲删关联工作树或依赖链接。

本轮仅更新资料。仓库其他源码、服务器、数据库、安装包和其他对话的未完成改动不在同步范围。
