# KST 工具接入与商业配置交接

本工作树基于 1.8.17，正在准备 1.9.0 发布。不能把前端构建或本机用例通过视为比赛工具已获准开放；具体发布状态见 `PLATFORM_FRAMEWORK_ACCEPTANCE.md`。线上启用前须先验收数据库迁移、管理员配置和目标平台的实际操作。

## 给工具开发同事

工具负责业务规则，平台负责身份、现场、权限和执行记录。不要在工具中生成客户授权、切换课赛通身份、创建第二个执行器，或保存平台账号密码。

接口定义在 `src/shared/ipc/toolkit-contract.ts` 和 `electron/automation/toolkit-runtime.cts`。实现一个 `ToolStages<Input, Data, Plan, Result>`，提交输入和结果校验器、版本化 descriptor，以及六个阶段：

| 阶段 | 工具负责 | 约束 |
| --- | --- | --- |
| detect | 识别当前身份、站点、账号、项目、场景和策略版本 | 不使用页面展示名代替可信账号标识 |
| read | 读取本次计划所需数据 | 不写业务、不上传页面原文或 Cookie |
| plan | 根据输入和读取结果生成可核对计划 | 账号、课程、站点或策略变化后旧计划失效 |
| execute | 按批准计划执行 | 写入前调用 `beforeMutation`；不绕过单执行器及授权 |
| verify | 回读同一业务对象，核对真实结果 | 按钮点击成功不是业务成功 |
| reconcile | 只读核对未知结果 | 不把重试提交当作核对 |

参考适配器在 `electron/automation/toolkit-examples.cts`：运费计算没有外部写入，配送模板复用既有 V2 页面适配和同对象核验。新适配器须编译进受审查代码，不接受后台下发任意 JavaScript、选择器脚本或远程执行函数。

开发时先跑输入错误、环境变化、重复执行、未知结果、回读失败和减少权限的用例。真实网站验收仍需独立签名配置与发行审批；加入商品权益列表不等于通过这两项审批。当前没有已验收的 V3 或正式比赛写入能力。

## 环境与分工

使用仓库 `.node-version` 指定的 Node 22、`package.json` 指定的 npm 12.2.0、Python 3.12 和项目约束依赖。不要使用学习目录的虚拟环境或替换其他工作树的共享依赖。

后端测试使用隔离 SQLite。真实控制面页面验收由 `node scripts/run-real-e2e.mjs` 创建本机测试服务、随机测试身份及证据目录，不需要也不得粘贴生产密码。MariaDB 事务和迁移需要另跑项目现有 MariaDB 验收；SQLite 通过不能替代生产数据库验收。

## 管理员配置顺序

1. 在“场景与本机运行权限”按用户或授权码分配场景。比赛入口为 `https://www.idtrade.cn/User/Contest`；只加入明确批准的完整 origin，协议、主机、端口均参与校验。
2. 对需按项目授权执行的课程，建立“项目与已审核课程”映射。映射只能使用已审核入口的课程指纹，不允许凭空填写另一个课程来绕过范围。
3. 如需管理员本机多账号，单独授权员工的站点、现场数量、截止时间与工具能力。客户授权码不能代替这项权限。默认 6 个现场，上限 10 个；自动执行仍串行。
4. 在“商品版本与项目权益”导入标准草稿，逐项核对后显式启用。39 元单工具从已审核工具中选择一项另建草稿；空权益模板不能直接销售。
5. 比赛、实训和单工具开单填写项目、站点和结束时间。确认实际到账后再发放授权。免费体验使用独立授权，不创建小额付款订单。
6. 在“成员结算台账”导入私有分配规则，配置成员与承担期间，再手填每单本次分配金额。先预览，确认后才形成成员明细。

新后台至少包含 `/admin/scenarios`、`/admin/local-runtime`、`/admin/commercial` 和 `/admin/team-ledger`。普通浏览器可以核对管理页面，但不能创建桌面账号现场。

## 金额与履约边界

收款、分配、实际付款是三个不同动作。新版订单确认收款不会自动产生成员收入；“已付”只登记线下付款和凭据，不连接银行转账。旧分润与代理佣金账本继续独立保留。

商品和授权保存购买时的价格、工具、服务和期限快照。改价应创建新版本，不改旧授权。599 元不继承旧 B 端批量权限；单工具 39 元只是次级购买选项，199 元仍为主要推荐。

服务完成记录包括次数、时长、执行员工和证据编号。部分退款需要分别核对客户剩余权益与团队分配：取消某项服务不自动表示该服务已经履行，资金调账也不自动恢复工具权限。再次退款会使旧权益审核失效。代理关联订单的部分退款在独立代理调整规则补齐前保持拒绝，不按全额退款误冲佣金。

免费体验的三项次数分别记录。可信执行成功才扣除；明确尚未提交可释放；未知结果保留占用并走同对象核验。未审核的注册或上品工具不能因体验额度存在而开放。

## 官网对齐与公开信息

平台用户价格页参考官网的商品内容与购买主次，199 元为主要推荐，39 元在套餐下方作为次级选购。UI 沿用平台自己的浅色画布、共享颜色与字号、卡片圆角和按钮密度；不复制官网的深蓝营销大区、超大价格或独立色板。后台只导出已启用商品的公开白名单数据，不包含成本、分配比例、成员或原始内部文件。

官网由独立对话维护。导出公开目录不会自动发布官网；发布前须比较商品版本、金额、期限与开放状态。管理端草稿不得进入公开目录。实际团队比例从仓库外的私有 JSON 导入，不复制到前端、测试夹具或公开交付包。

`scripts/check_public_catalog.py validate <公开快照.json>` 校验公开字段、稳定 SKU、精确金额和目录内容哈希；`compare <平台快照.json> <官网快照.json>` 要求两端版本及公开内容一致。这两个命令只读本地 JSON，不连接数据库、不启用商品、不发布官网。官网当前仍是独立静态价格数据，尚需在官网构建环节接入稳定 SKU 和目录快照；页面报价一致不等于版本自动同步已完成。

## 迁移与发布要求

迁移 `20261015_framework_commerce` 仅新增表，不替换旧套餐、历史授权或旧台账，不自动种入正式价格和成员比例。回滚检查到新表有数据时会拒绝删表，必须先备份和核对。

新客户端的场景策略读取失败时停止新的受控操作，不把网络失败当成“没有限制”。因此部署顺序必须先升级并验收后端合同，再交付匹配客户端；不能单独把客户端推送到旧后端。

用户已授权在正式门禁通过后部署，但不自动激活商业草稿。候选验收应覆盖至少三个管理员独立账号现场、客户换号清理、站内正常跳转和跨站拒绝、额度并发与未知结果、退款与已付调整，以及新老授权兼容。1.9.0 保留现有旧协议兼容，不因版本号到达旧文档中的兼容节点而直接删接口。
